# 文案与事实核验规则

## 先核实，再压缩

每个候选项目先建立一条事实记录：

- 仓库全名和链接，保持原拼写与大小写。
- 项目解决什么问题、核心功能是什么；优先依据 README、官方文档或项目发布说明。
- 如需展示 Star、Fork、排名或新增量，记录数值、采集时间、统计区间和数据来源。
- 区分项目自述、第三方评价、平台榜单与自己的概括，不把概括伪装成官方说法。

事实核对的来源优先级：

1. 项目官方 GitHub 仓库、官方文档、官方发布记录。
2. GitHub 官方页面或 API 中可直接核对的字段与时间。
3. 有明确日期和统计方法的可信榜单或数据服务。
4. 原日报仅作为待核实线索，不能单独证明争议数据。

如果无法访问来源，写明“未能核实”并删除该主张，或在交付中保留待核实标记。不要推断版本、能力、用户数、Star 增长或排名。

## 指标口径

- “Star 总数”是当前累计值；“新增 Star”必须有明确时间窗口和可核查数据。
- “热门”需说明依据，例如用户提供的榜单、某时间段新增 Star 或明确的筛选清单。不要写成“GitHub 全站第一”等未经支持的结论。
- 数字要带单位、统计时点或区间；无法在封面清楚说明口径时，宁可不放数字。
- 相对日期（今天、昨日）转换成明确日期，并注明使用的时区；不确定时保留日报给出的日期并标注时区未知。

## 奥卡姆剃刀：保留最少但足够的信息

每个项目只留：

1. 项目名称。
2. 一句话说明它做什么或解决什么问题。
3. 只有在能帮助读者判断价值且来源可靠时，才补一个指标。

删掉重复卖点、营销形容词、背景长文、未验证比较、无关技术细节和对封面无帮助的标签。功能句优先用“动作 + 对象 + 结果”表达；将术语翻译成简洁中文，但不要扩大能力边界。

## 建议长度

- 主标题：一行，优先 8–16 个汉字。
- 副标题：一句，约 12–24 个汉字。
- 项目名：保留官方名称，必要时换行，不自行翻译仓库名。
- 项目描述：每条约 12–26 个汉字，尽量一行或两行内。
- 底部总结：一句短判断，不重复副标题，也不制造趋势结论。

长度是排版参考，不得为了塞字而缩小到难以阅读。

## 封面文案示例（仅示范结构，不是事实）

- 项目：`sample-org/agent-kit`
- 一句话：`把重复的 AI 工作流封装成可复用工具`
- 可选指标：只有当天已核实口径时才加

不要将这个示例当成真实仓库或项目推荐。
